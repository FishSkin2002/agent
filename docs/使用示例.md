### OPSD vs. Vision-OPD 对比

**两篇论文分别是：**
- **OPSD**：*Self-Distilled Reasoner: On-Policy Self-Distillation for Large Language Models*（Zhao et al., arXiv 2601.18734v4）
- **Vision-OPD**：*Learning to See Fine Details for Multimodal LLMs via On-Policy Self-Distillation*（Yuan et al., arXiv 2605.18740v4）

两者是**同一方法论母体的“原始提出”与“跨模态迁移”**关系，Vision-OPD 明确把 OPSD 作为框架来源（引用为 [75]）并列为对比基线。

#### 1. 共享的核心框架

两者都采用“单模型、双角色、on-policy”的自蒸馏：从同一个模型实例化两个条件策略，学生生成 rollout，教师在同一学生前缀上给出逐 token 分布，最小化沿学生自身轨迹的 per-token 散度，梯度只回传学生 logits。

- OPSD：学生 `p_S(·|x)` 只看题目，教师 `p_T(·|x, y*)` 额外看 ground-truth 解/答案；"minimizes the per-token divergence D(p_T‖p_S) along the student's rollout… gradients backpropagate only through the student's logits"（p.2）；最终"enabling the model to serve as its own teacher without requiring external reward models or larger teacher models"（p.4）。
- Vision-OPD：学生 `p_S(·|x, q)` 看整图，教师 `p_T(·|x', q)` 看证据中心裁剪图；"The student generates on-policy rollouts y ~ p_S, and the per-token divergence D(p_T‖p_S) along these rollouts provides dense supervision. Gradients flow only through the student's logits"（p.4）。

#### 2. 关键差异

| 维度               | OPSD (2601.18734v4)                                          | Vision-OPD (2605.18740v4)                                    |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 特权信息的**通道** | **文本**：已验证的解答/答案 y*（p.4）                        | **视觉**：evidence-centered crop（区域证据），整图归学生（p.4） |
| 任务域             | 竞赛级数学推理，Qwen3-1.7B/4B/8B（p.7）                      | 细粒度视觉理解，Qwen3.5-4B/9B；V*Bench、ZoomBench、HR-Bench 4K/8K、MME-RW EN/CN（p.6–7） |
| 动机假设           | 有 GT 解却未被利用；on-policy 蒸馏通常需更大外部教师（摘要、p.2） | 观察到 **regional-to-global perception gap**：同一 MLLM 在证据裁剪图上答得更准，说明瓶颈是“聚焦证据”而非局部识别能力（摘要、p.9） |
| 训练数据           | 复用现有数学推理数据集（含 GT）                              | 自建 **6.2K 合成三元组** (x, x', q)：小区域检测→Qwen3.5-397B 出题→投票一致率 >0.75 才保留（p.4） |
| 散度选择           | **forward KL** 最好；reverse KL、JSD(β=0.5) "limited or negative improvements"（p.7） | **JSD(β=0.5) 最好**，且用 top-K(K=100) logits + tail 项近似（p.5, p.8, Table 4） |
| 教师处理           | 教师=同权重+额外上下文（无教师正则需求）                     | 教师需**正则化**：无正则"diverges entirely, collapsing to near-zero accuracy"；冻结初始策略 79.40、trust-region 79.22、**EMA(α=0.05) 最优 79.68**（p.8, Table 3） |
| 训练配置           | LoRA r=64、α=128、lr 5e-6、batch 32、**100 步**、学生生成上限 1024（GRPO 为 16k）（p.14） | 用 JSD + top-K + EMA 教师；同样只用图像–问题对，不需人工标注或外部教师模型（p.5） |
| 主要卖点           | **token 效率**：100 步内超过 GRPO 且 token 用量远少；GRPO 因 reward 方差塌缩停滞（p.6–7） | **免标签**、缩小区域–全局 gap、可媲美更大开源/闭源与 Thinking-with-Images 智能体模型（摘要、p.6、p.9） |

#### 3. 结果层面的对比

- OPSD：Qwen3-8B 基座（Instruct）三项平均 61.8 → OPSD 峰值 64.8，高于 GRPO 峰值 64.0、SFT 59.8；Qwen3-4B 上 OPSD 峰值也略优于 GRPO（p.7, Table 2）。其结论是"matches GRPO with significantly improved token efficiency and outperforms SFT"（p.6）。
- Vision-OPD：在自身 Table 1 中"consistently improve over the corresponding Qwen3.5 baselines across all benchmarks"，并在同一数据/同一骨干下胜过 SFT-on-self-teacher、GRPO、DAPO、以及 **OPSD（用 GT 标签作特权信息）**（p.6 基线段落 + p.7 Table 1）。这构成本文对 OPSD 的直接实证比较：在细粒度视觉任务上，“区域视觉特权信息”比“文本 GT 答案特权信息”更有效。
- 诊断性验证：Vision-OPD 还追踪训练中的 regional-to-global gap，显示差距持续收窄，末态小于大得多的开源/闭源模型（p.9）。

#### 4. 怎么理解两者关系（几点判断）

1. **OPSD 定义范式，Vision-OPD 定义特权信息的另一种来源**：前者把“数据集里已有的 GT 解”当作免费特权信息；后者把“同一模型自己看局部图的能力”当作特权信息，从而摆脱对答案标注的依赖。这也解释了为什么 Vision-OPD 的数据必须自己合成（需要 paired crop + 仅在全图上难以回答的问题）。
2. **教师—学生的差距来源不同，导致稳定性处理不同**：OPSD 的教师和学生差在"是否看到解答文本"，天然有差距；Vision-OPD 只差在视觉输入，同权重自蒸馏会共适应崩塌，因此必须用 EMA/trust-region 冻结教师（p.8）。这是把 OPSD 迁移到视觉时最实际的一个工程量。
3. **一个共同的潜在弱点**（延伸阅读，非两篇原文结论）：CV-OPD（arXiv 2610.13264v1）指出，用"答案/提示"作条件做 OPD 的模型即使遮住关键图像区域仍能答对，说明蒸馏可能学到捷径而非真正依赖视觉证据；这对 OPSD 式“答案作特权信息”以及 Vision-OPD 的“答案级监督信号”都构成值得警惕的检验。

**一句话总结**：OPSD 是数学推理上"用 GT 解当自教师"的 on-policy 自蒸馏原型（forward KL、100 步、重 token 效率）；Vision-OPD 把同一目标函数搬到多模态细粒度理解，把特权信息换成区域裁剪图（JSD + top-K、EMA 教师、6.2K 自合成数据），并用 regional-to-global gap 作为机理解释与诊断指标，同时在实验中把 OPSD 作为需要 GT 的基线击败。

**Rubrics as Rewards: Reinforcement Learning Beyond Verifiable Domains**
Anisha Gunjal, Anthony Wang, Elaine Lau, Vaskar Nath, Yunzhong He, Bing Liu, Sean Hendryx（Scale AI）
arXiv:2507.17746v2 [cs.LG]，2025-10-03｜Zotero itemKey `TGFN53VY`｜原文 PDF `5MF43JWE`（你库里另一份 `Y4GLKQVT` 是中英对照 compare 版）

#### 一句话主旨

**把“评估用到的 rubric（评分清单）”直接当成 RL 的奖励函数**：用 LLM 为每道题合成一组带权重的、可独立判定的清单式判据，让 LLM judge 逐条打分并聚合成标量奖励，驱动 GRPO 在线训练，从而把 RLVR 从“有唯一正确答案”的数学/代码扩展到医学、科学这类多维度、无二值正确性的领域（p.1–2）。

#### 1. 动机：夹在 RLVR 与偏好模型之间

- RLVR 在数学/代码上有效，因为它有可验证的自动判分（p.1）。
- 现实推理任务"缺乏易验证答案"，常用话术是 preference reward model，但后者"tend to overfit superficial artifacts (e.g. response length, formatting quirks, annotator biases)"，而且要海量成对比较（p.1）。
- 实例级 rubric 此前主要用于**评测**（如 HealthBench），"their application in on-policy training for expert-level reasoning is largely unexplored"（p.1）。

RaR 的定位就是这两者之间的中间地带：比二值正确性更有表达力，比偏好排序更少人为伪影和运营开销（p.1）。作者强调自己与并行工作（rubric 用于 DPO/偏好数据、安全对齐）的区别是"closes the rubric-to-learning loop"，把 rubric 当 reward function 喂进 on-policy RL（p.2）。

#### 2. 方法

##### 2.1 形式化（p.2）
每个 prompt $x$ 关联 $k$ 条 rubric $\{(w_j, c_j)\}$，$w_j$ 为权重，$c_j:(x,\hat y)\mapsto\{0,1\}$ 是二值判据函数（实验用二值，但可扩展为连续分数）。

##### 2.2 两种奖励聚合方式（p.2–3）
- **Explicit aggregation**（式1）：逐条独立判分后加权归一
 $r(x,\hat y)=\sum_j w_j c_j / \sum_j w_j$。归一化让不同题目的奖励可比（p.3）。
- **Implicit aggregation**（式2）：把 prompt、回答与全部 rubric 一起交给 LLM judge，让它"holistically"直接给一个标量，**免去手工调权重**（p.3）。

##### 2.3 一个理论观察（Remark 1, p.3）
作者证明 RLVR 是 rubric 奖励的**特例**：$k=1, w_1=1$，$c_1$ 退化为单一可验证正确性函数（exact match / 测试用例）。因此 rubric RL 严格推广了 RLVR，支持多维度、可加权、主客观混合的监督。

##### 2.4 rubric 怎么来的（p.3–4）
四条设计准则（desiderata）：**Expert grounding**（反映领域必备事实与推理步骤）、**Comprehensive coverage**（事实/逻辑/完整性/风格/安全，含负面 pitfall 项）、**Criterion importance**（权重体现优先级，事实正确性应压过文风）、**Self-contained evaluation**（每条可独立判定，判者不需外部知识）（p.3–4）。

生成流程：因缺少人工 rubric 数据，用强 LLM 以**金标准参考答案作为专家监督的代理**，为每题合成 **7–20 条**自包含条目，每条同时给数值与类别权重，实验中采用类别标签 **Essential / Important / Optional / Pitfall**；生成模型为 o3-mini 与 GPT-4o（p.4）。产出并开源 **RaR-Medicine**（20,166 题，平均 7.5 条 rubric，p.12 Table 4）与 **RaR-Science**（20,625 题，p.13 Table 7）。

##### 2.5 训练设置（p.4, p.14 Table 10）
GRPO，基座 Qwen2.5-7B，每 prompt 16 rollouts，有效 batch 96，lr 5e-6，constant_with_warmup（10% warmup），max_length 3584，温度 1.0，300 步，8×H100；判分模型 gpt-4o-mini。

##### 2.6 对比方法（p.4–5）
无 rubric 基线：Off-the-shelf、**Direct-Likert**（judge 直接给 1–10 分）、**Reference-Likert**（对照参考答案给分）。Rubric 类：**RaR-Predefined**（全库共用固定通用 rubric）、**RaR-Explicit**（实例级 + 式1，权重映射 Essential 1.0 / Important 0.7 / Optional 0.3 / Pitfall 0.9）、**RaR-Implicit**（实例级 + 式2）。

#### 3. 结果

| 方法                | HealthBench 总分 | GPQA-Diamond |
| ------------------- | ---------------- | ------------ |
| Qwen2.5-7B          | 7.7              | 31.7         |
| Qwen2.5-7B-Instruct | 22.7             | 35.0         |
| Direct-Likert       | 25.5             | 34.8         |
| Reference-Likert    | 28.9             | 36.5         |
| RaR-Predefined      | 12.5             | 31.7         |
| RaR-Explicit        | 29.7             | 36.9         |
| **RaR-Implicit**    | **31.2**         | **37.6**     |

（p.6 Figure 2；正文称相对增益最高 31% / 7%，p.5–6）

在 HealthBench-1k 上的 rubric 质量消融（Table 1, p.7）：Expert-Answer-SFT 20.4 → Simple-Likert 23.9 → Reference-Likert 31.7 → 无参考答案的合成 rubric 32.0 → **有参考答案的合成 rubric 35.9** → 人工撰写 rubric 34.8。即"合成+参考"≈"人工"，而"纯合成无参考"明显掉队。

#### 4. 几条值得记住的发现

1. **必须 instance-specific**：固定通用 rubric 的 RaR-Predefined 表现明显差于实例级 rubric，因为通用条目抓不到题目特定要求与典型失败模式（p.6）。
2. **Implicit 略胜 Explicit**：加权和可控但"brittle"，隐式聚合省调参、整体最好；作者认为二者取舍取决于应用（p.6）。
3. **对小 judge 收益最大**：rubric 引导下所有尺寸 judge 的 pairwise 偏好准确率都提升，小模型提升最多、与大队列差距收窄；rubric 打分更集中（0.250–0.279）vs Likert（0.220–0.254）（p.6, p.14；Table 11 中 Qwen-7B-Instruct 由 22.0→26.7）。
4. **专家 grounding 是关键**：rubric 质量受参考答案质量约束；无参考答案时 GPT-4o 生成最好（34.2）但仍不及 o3-mini+参考（35.9）（p.8 Table 3）。
5. **rubric 设计消融（p.8 Table 2）**：Essential-Only 34.9 < All 37.2 ≈ No-Pitfall 37.2 < **No-Categorical-Labels 38.8**。也就是说——**权重标签本身几乎没贡献，甚至去掉略好**，这与"implicit 最优"一致；而作者把 pitfall 无效归因于合成模型难以为本模型预判真实失败模式（p.8）。

#### 5. 局限与阅读时的注意点

- 作者自陈：只覆盖医学与科学两域、只比较两种聚合、judge 用现成 LLM（p.9）。
- 我阅读时发现的三处需要留意：①**绝对分数偏低**（HealthBench 上最强也只有 31.2%），"31% 相对提升"的分母是较弱的 Direct-Likert；②小规模不一致：6 节正文说用 "3.5k prompts" 训练，但同一节比较 rubric 生成模型时又说 "remaining 4k training examples"（p.7–8）；③HealthBench 官方评分用的是**医生撰写的 rubric**，与训练用的合成 rubric 同源同格式，评测对方法本身有"主场优势"，GPQA（多选题）上的增益（+2.8 绝对）才更能说明泛化（p.5–6）。

#### 6. 与你之前关心的 OPD/自蒸馏的关系

若把它接到上一轮的 OPSD / Vision-OPD 语境：RaR 提供的是**外部 LLM-judge 的标量奖励**（GRPO 的 advantage 来源，p.4），而 OPD 系列是用**同模型的教师分布做逐 token 监督**，不需要 judge 也不需要 reward model。前者解决"奖励怎么定义"，后者解决"监督信号怎么变稠密"——两者可以叠加（rubric 奖励做 RL、自蒸馏做稠密化），但 RaR 本身不涉及蒸馏机制。
