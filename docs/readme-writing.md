# README 编写约定

## 板块顺序

1. 标题使用“论文知识检索 Agent”，下方用一句话说明项目用途。若已有面向项目使用者的实验报告，可在简介后用加粗文字和引用块链接。
2. 项目目录。用带简短用途注释的目录树展示根部文件和文件夹。配置和输出目录实际出现后，再分别展开说明。
3. 输入与输出。检索入口实现后，用一个实际支持的问题和对应结果展示格式。
4. 检索结果的核验。实现证据定位或评测后，独立说明用户如何核对结果。
5. 环境准备。列出运行当前入口所需的安装命令和环境条件。
6. 主要脚本使用说明。先按根目录运行脚本分类，再按用途给出命令。

板块随可用功能补齐。README 使用纯文字和 Markdown，省略 emoji 和空板块。教学讲解放在聊天或本地教学笔记中。

## 目录与运行示例

- 根目录总览只列一层。配置目录另行展示到文件夹一级。输出目录选一次典型运行，逐项标明文件用途、可变文件名、生成条件及仓库外的路径。
- 每个根目录运行脚本先用一句话说明用途。每种用途给出一条填好必需参数的命令，配对参数和该用途必需的开关一并写全。路径占位符在命令旁说明。工具目录的内部脚本不列为主要入口。
- 安装示例以项目实际依赖为准。Conda 创建与激活命令均使用用户指定的环境名 `agent`。
- README 保持简短。参数多到需要单独参考时，在主要脚本板块链接它，按脚本和用途列出“参数”“默认值”“可填内容及作用”，写清必填、互斥、配对和条件默认值。修改运行入口时同步核对示例与参数说明。
